2026-10-15 — Prototype Phase 0 réalisé et vérifié avec Go 1.23.4. Fonctionne :
interface commune et runner injectable ; capture dnf en niveaux 1/2/3,
détection de l'incohérence par doctor, capture Flatpak avec repli sur les
répertoires et avertissements de divergence des portées ; sortie JSON de
capture et commande doctor. Build et vet passent, gofmt ne signale aucun
fichier, et les 13 tests unitaires passent, dont les scénarios d'incohérence
simulés par mocks. Vérification locale : doctor voit dnf fonctionnel (502
éléments), Flatpak fonctionnel (6 apps) et apt absent ; capture dnf niveau 1
(502 paquets) et Flatpak niveau 1 (6 apps, 2 remotes).

Ne fonctionne pas / non vérifié : le repli dnf niveau 3 n'a pas été exercé sur
une vraie base DNF ; il requiert sqlite3 et la disponibilité de la table rpm
dans history.sqlite. Pas de blocage pour build, vet ou tests. Prochaine action
recommandée : valider ce dernier recours sur une base DNF dédiée, puis reprendre
P0.3 (échantillon des correspondances Repology).

2026-10-15 — Schéma YAML versionné (schema: 1) publié dans pkg/manifest,
avec lecture/écriture, validation, avertissement sur les chaînes ressemblant
à des secrets et préservation des champs inconnus. Tests round-trip et champs
inconnus validés. BuildManifest convertit les captures dnf/Flatpak et les
métadonnées système ; `capture` produit YAML par défaut, JSON, dump brut avec
`--format raw`, et accepte `-o`, `--only` et `--exclude`. Exemple réel produit :
Fedora 44, amd64, capture dnf (502 paquets) et Flatpak (6 apps, 2 remotes) ;
les divergences Flatpak vont sur stderr, pas dans le manifeste.

Fonctionne : `gofmt`, build, vet et les 24 tests passent ; le YAML réel se relit
et se valide. Non réalisé : dépôts, snaps, paquets de langages, services, cron,
configs et binaires non gérés restent vides ; pas de résolveur, plan ni
exécuteur. Aucun blocage pour cette phase. Prochaine action recommandée :
P0.3, échantillon des 200 correspondances Repology vérifiées manuellement.

2026-10-15 — Prototype P0.3 implémenté : client API Repology avec User-Agent,
limitation à 1 requête/s, retries exponentiels, cache local de 7 jours,
base SQLite pure-Go, commandes `update-db` et `resolve`, et documentation de
bootstrap dans data/README.md. Décision technique : utiliser l'API uniquement
pour l'échantillon exploratoire P0.3 ; remplacer ce bootstrap par les dumps
Repology dans la CI de production (PRD §12).

Échantillon CSV généré : 200 paquets Fedora vers debian_13 (201 lignes avec
l'en-tête), répartis en 77 exact, 1 equivalent, 3 ambiguous et 119 not_found.
Le CSV est dans `/tmp/sample-200.csv` et attend la vérification manuelle ;
P0.3 reste donc non cochée. Une première importation de 502 projets (9 min
20 s) a révélé un champ de nom Repology différent (`binname`/`visiblename`) ;
ses enregistrements de noms vides ont été purgés. Après correction, le
bootstrap réseau a atteint 293/502 en environ 17 min (273 réponses réseau,
13 réponses cache, 7 erreurs réseau/réponse lente) avant arrêt pour éviter
d'insister sur les délais croissants. Un lot de contrôle hors ligne de 50
projets a réussi en 9 s, avec 14 candidats ajoutés, 0 404 et 0 erreur.
Base locale : 490 projets conservés, 137 candidats non vides, 0 nom vide,
116 KiB. Aucun 404 Repology observé ; de nombreux projets n'ont aucun candidat
dans Debian 13, et quelques requêtes tardives ont subi des timeouts/retries.

Fonctionne : API et cache, import idempotent, résolution CSV et tests de
classification/échappement ; les 38 tests passent, y compris la compilation
avec `CGO_ENABLED=0`. Limite : la base ne contient pas encore de données
fraîches pour les 502 projets ; le CSV des 200 premiers a été construit avec
les projets traités avant l'arrêt réseau. Prochaine action recommandée :
vérification manuelle de `/tmp/sample-200.csv` par l'utilisateur, puis
reprendre l'import des projets restants si nécessaire.

2026-10-15 — Fiabilisation P0.3 : le catalogue des dumps Repology ne propose
pas de dump filtré par dépôt. Le dump SQL PostgreSQL complet annoncé est
d'environ 2,46 Go compressé, requiert PostgreSQL et ses extensions Repology ;
il n'a pas été téléchargé ni restauré. Repli sur l'API avec keep-alive,
timeout de 60 s et jusqu'à cinq tentatives exponentielles, en conservant la
limite d'une requête/s. L'import local accepte des dumps JSONL filtrés, mais
ce n'est pas un import direct du dump SQL officiel.

La résolution essaie désormais des noms candidats (exact, normalisés,
minuscules), y compris les suffixes de sous-paquets, `lib*` et `python3-*`,
puis une recherche fuzzy par distance de Levenshtein à seuil resserré. Le
diagnostic `resolve --explain NetworkManager-adsl` trouve
`network-manager` via le projet Repology `networkmanager`. L'import API
complet reste partiel : 493 projets connus dans la base, 140 paquets Debian
13 enregistrés, aucun nom de paquet vide ; base SQLite de 116 KiB. Le
bootstrap complet des 502 paquets n'a pas été achevé, donc les absences ne
sont pas toutes des absences confirmées de Debian.

Échantillon régénéré après le resserrage fuzzy : `/tmp/sample-200.csv`,
200 paquets (201 lignes avec en-tête) : 79 exact, 8 equivalent,
4 ambiguous et 109 not_found. La recherche normalisée permet notamment de
rapprocher les sous-paquets NetworkManager ; le seuil fuzzy plus strict a
réduit les ambiguïtés de l'échantillon de 8 à 4. Limites observées : paquets
spécifiques à Fedora, firmware, composants découpés différemment, écarts de
versions entre dépôts, couverture API interrompue et rapprochements fuzzy
qui restent indicatifs. Tous les 62 tests Go passent, ainsi que build, vet
et compilation sans CGO.

Décision technique : API pour l'exploration P0.3 ; dumps Repology à traiter
en CI pour produire la base de production (PRD §12), après mise au point d'un
pipeline capable d'importer le dump complet. P0.3 reste en attente de
vérification manuelle : les statuts `not_found` de cet échantillon ne doivent
pas être interprétés comme des absences certaines tant que la couverture de
la base est incomplète. Prochaine action recommandée : vérifier manuellement
`/tmp/sample-200.csv`, en particulier les correspondances équivalentes et
ambiguës.
